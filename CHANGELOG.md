# Changelog

## v0.3.0 (2026-11-16)

### Added

- **Live dictation** (#19): a dictation is recognized while you speak. The audio is cut at pauses (0.6 s, pieces of 2 to 20 s) and each piece goes to the engine at once, so after the hotkey only the last piece is left: a 60 s dictation is pasted about 0.8 s after the stop instead of about 8 s (Arc GPU, synthetic speech). The text recognized so far shows in the dictation window. The language of the first piece is kept for the whole dictation, and the text so far is passed to Whisper as the prompt. The closing-line cut and the hallucination filter run once on the joined text; pasting, the target window and the clipboard rules are unchanged. If a piece fails, the whole recording is recognized the old way. WER on the synthetic dictation set: 1.9 % live vs 2.7 % whole. On by default; Settings → Dictation → *Recognize while speaking* (new key `dictation_live`). Numbers in `docs/benchmarks.md`.
- `tools/benchmark_engine.py --live [--live-model M] [--live-runs N] [--live-during-meeting]`: WER whole vs live, and the time from the stop to the text.
- **Live meeting transcription** (#16): a meeting is transcribed while it is recorded, so the transcript is ready soon after the stop: 4.1 s instead of 90 to 138 s for 8 minutes in Auto language mode, 23 s instead of 54 to 56 s with Polish (Arc GPU, synthetic speech). The transcript is the same as without it: the live results are reused only for chunks that the transcription after the stop cuts with the same range and the same samples, and the rest is recognized after the stop. The Meeting screen shows the text recognized so far while recording, and the text so far is saved in the session folder after every chunk, so a crash keeps it (the recordings list shows it as a partial transcript). Dictation keeps priority: no meeting chunk starts while a dictation is spoken. When the computer cannot keep up, the live work stops for that recording and the rest is transcribed after the stop. Settings → Transcription → *Transcribe while recording* (new key `meeting_live`; automatic by default: on in Auto language mode on a GPU or NPU, off on the CPU and with a forced language, where a dictation could wait for a 5-minute chunk). Numbers in `docs/benchmarks.md`.
- `tools/benchmark_engine.py --live-meeting [--meeting-language L] [--speed X] [--louder-from MIN]`: the time from the stop to the transcript with and without live transcription, whether the transcripts are identical, and dictation latency meanwhile.

## v0.2.1 (2026-11-16)

### Added

- **`Ucho-Setup.exe`**: a one-click installer (Inno Setup 6.7.3, about 2.5 MB). It installs for the current user without admin rights into `C:\Users\<you>\Ucho\app`, then runs `install.ps1` in a console window (Python, libraries, model), adds Ucho to Settings → Apps with an uninstaller that runs `uninstall.ps1` first, and offers to start Ucho at the end. It refuses to run while Ucho is open. Running it again, or a newer version, updates the program files and keeps settings, models, `.venv` and recordings. `Ucho-Setup.exe /VERYSILENT` installs without questions. The zip with `install.cmd` stays for computers that block `.exe` files. Not code-signed yet: Windows SmartScreen asks for *More info → Run anyway*, and Smart App Control may block it outright (then use the zip).
- `tools/build_package.py --installer` builds the installer next to the zip from the same staged files; `SHA256SUMS.txt` lists both. CI compiles the installer on every push.

## v0.2.0 (2026-11-16, first public release)

### Upgrading from v0.1

v0.1 was an internal build. To upgrade it, extract `Ucho-Windows.zip` over the old folder (the package now holds `Ucho\app\`, so extracting it to `C:\Users\<you>` updates `C:\Users\<you>\Ucho\app`) and run `install.cmd` again. Settings and old recordings are carried over (see *Compatibility* below). Close the old *Ucho Dyktuj* window first: it holds Ctrl+Shift+Space.

### Added

- **Delete recording**: on the transcript screen (or the Delete key on a recording in the list), after a confirmation that names the meeting, the whole session folder is deleted permanently. Refused while the session is being recorded, transcribed or summarized; a session waiting in the queue is taken out of it. While one of its files is open nothing is deleted; if a deletion stops halfway, the rest is in a `.ucho-deleted-…` folder that Ucho removes at the next start.
- **Delete audio after** (Settings → Storing recordings): Never (default), 7, 30 or 90 days. Removes only the audio of recordings with a complete transcript (not stopped, no errors, at least one recognized utterance), at start and then once a day; transcripts and summaries stay, and the list shows "audio deleted". Counting the recordings affected by a new choice runs in the background. A value set by hand in `settings.json` must be a whole number of days, otherwise it means never. New `meta.json` keys: `transcript_complete`, `transcription_cancelled`, `transcription_errors`.
- **Transcription queue**: a recording stopped while another one is still being transcribed or summarized waits in a queue and starts on its own, instead of failing with "Another transcription is running". Cards show "Queued, #2", the status pill "2 waiting". *Transcribe again* uses the same queue.
- **Double-click install**: `install.cmd` runs `install.ps1` without changing the execution policy and keeps the window open at the end and after an error (`install.ps1 -Pause`). Started from inside the zip, it asks you to extract the zip first.
- The installer logs every run to `install.log` in the app folder, with the output of pip, winget, the hardware check and the model download (a failed download leaves its error there; progress is one line every 15 s, not a progress bar), and says where the log is when something fails. `install.cmd` keeps the window open with its own message only when PowerShell could not start the script at all. Installer and uninstaller messages are in Polish on a Polish Windows and in English otherwise (they used to be Polish everywhere).
- The installer ends with a summary: how to start Ucho, and the exact `claude mcp add -s user ucho -- ...` command with the paths of this installation.
- `uninstall.cmd` / `uninstall.ps1`: remove the shortcuts, the start-with-Windows entry and, after a question, `.venv`, models, settings and logs. Only shortcuts and entries that point to this app folder are touched. Recordings are deleted only after a separate prompt where you type a word, and only session folders Ucho created (named `yyyy-MM-dd_HH-mm...` and holding an Ucho audio track or `meta.json`), listed by name before the prompt. Nothing is deleted from a recordings folder that is the user folder, Documents, Desktop, Downloads, a OneDrive root or a drive root. Junctions and symbolic links are removed as links, never followed.
- Hardware detection and automatic model choice (`ucho/hardware.py`, `docs/hardware.md`). `python -m ucho.hardware` prints the hardware profile and a recommended Whisper model, device and dictation model with the reasons; `--benchmark` measures the real-time factor on a synthetic signal and steps one row down below 1.5x; `--save` writes the result to the settings.
- New settings keys `dictation_model` and `hardware_profile`.
- `ucho/session.py`: one reader of recording folders for the app and the MCP server, for both the current and the v0.1 format.
- **New interface on the design system** (W2). Theme from `design/tokens.json`, light and dark, following the Windows app theme unless set in Settings. Sidebar with Meeting, Dictation, Recordings and Settings. Recording screen with a status pill (Ready / Recording / Transcribing), a round REC button in the action color that turns clay red with a slow pulse while recording, timer, both level meters, meeting name and the last three recordings. Recordings list with search in titles, summaries and all transcripts (diacritics-insensitive). Transcript view with monospaced timestamps, speaker colors, *Copy all* and *Open folder*. Screenshots in `docs/screens/`.
- **First-run wizard**: interface language, recordings folder (warns about OneDrive), hardware profile and recommendation with an optional speed measurement (`hardware.benchmark` / `after_benchmark`), note on consent and headphones.
- **Settings → Hardware**: profile, recommendation with reasons, *Measure again*, device GPU / CPU / NPU (experimental, asks first: the first compile takes about 3 minutes) / AUTO, transcription model with download.
- **Keyboard access**: every control is reachable with Tab, Enter/Space activate it, a focus ring in the focus color shows where you are. Layout fits a 1366x768 screen at 125 %.
- **One app for meetings and dictation** (W3): one process, one shared Whisper engine (`ucho/engine.py`, a worker thread with a priority queue; a meeting transcription yields after every chunk, so a 10 s dictation is answered in 1.2-1.7 s while a meeting transcribes, measured), one tray icon, both global hotkeys always active (Ctrl+Alt+R, Ctrl+Shift+Space, Esc while dictating), single instance (a second start shows the running window), one AppUserModelID, Jump List tasks *Record a meeting* and *Dictate*, taskbar progress, optional start with Windows.
- Window layout setting: one window with Meeting and Dictation modes (default) or the tray icon as the hub with a small separate dictation window.
- Dictation model setting: the transcription model (one model in memory) or a separate one; option to keep it loaded. Default from the hardware recommendation.
- `python -m ucho --smoke-test` (W4d): builds the whole UI without audio capture or a model, walks through every screen, both layouts and both themes, and exits with 1 when anything logged an error. CI runs it on windows-latest with `requirements.txt`.
- `python -m ucho --dictate | --record | --minimized`.
- `tools/screenshots.py` (window screenshots on synthetic data) and `tools/benchmark_engine.py` (dictation latency during a transcription and a 20-sentence TTS set for WER, synthetic speech from the offline Windows voice). Results in `docs/benchmarks.md`.
- `ucho/archive.py`: the archive search of the MCP server, now shared with the app.
- **Optional Parakeet backend** (W6): NVIDIA Parakeet TDT 0.6B v3 (fp32 ONNX, CC BY 4.0) through sherpa-onnx, CPU only. Not installed by default: `install.ps1 -WithParakeet` adds the pinned `sherpa-onnx` package (`requirements-parakeet.txt`); the model (~2.5 GB, pinned revision) is then offered in Settings → Hardware and downloaded on demand. Same transcript segments as Whisper, so the transcript files, search and MCP server do not change. Measured on synthetic Polish speech: within 1 pp WER of Whisper large-v3 and 3 to 10 times faster on the CPU, but clearly worse with English phrases in Polish sentences; never recommended automatically, Whisper stays the default. The int8 export was rejected (7.6 % vs 2.7 % WER). Details in `docs/benchmarks.md`.
- `tools/benchmark_wer.py --backend parakeet [--threads N]`; the JSON report also records the backend and the peak working set.

### Changed

- **Dictation and the clipboard**: text that Ucho puts on the clipboard is kept out of Windows clipboard history and cloud clipboard sync. Dictated text is pasted only into the window that was active when the dictation started. The previous clipboard text comes back only after that window has actually taken the dictation; if it is slow (remote desktop, a busy app), another program reads the clipboard, or only the desktop or taskbar is in front, the dictation stays on the clipboard with a "press Ctrl+V" note and the old text is not restored. In Enter mode, Enter is pressed only after the text was pasted.
- **Search without Polish characters**: "zlotych" finds "złotych" and "lodz" finds "Łódź" (also "ł", which the search index did not fold), in the app and in the MCP server. Highlights follow the same word rules (words joined by "_", accents typed as combining characters).
- Key names follow the interface language ("Spacja" in Polish).
- **Mouse wheel**: Settings and the Recordings list move about three lines per wheel notch (it was 20 px, under one line) (#8).
- **Transcript screen in a narrow window**: the progress bar and its text have their own row under the buttons, and *Delete recording* moves under the other buttons when one row is too narrow. Before, the progress text was cut at both ends, the percentage too, and ran under the Delete button (#14).
- **Invented closing lines**: subtitle endings that Whisper appends after the last sentence ("Dziękuję za uwagę.", "Napisy stworzone przez…", "Thanks for watching") are cut from the end of a dictation and of a transcript segment; before, they were dropped only as a whole utterance. A plain final "Dziękuję." stays (#9).
- **Microphone list**: Settings → Audio devices lists each microphone once, with its full name, from WASAPI (the API the system-audio loopback already used). Before, every microphone appeared up to three times (MME with names cut to 31 characters, DirectSound, WASAPI), next to the "Sound Mapper" and "Primary Sound Capture Driver" entries. The default microphone is the WASAPI default too. The chosen devices are kept by name (`microphone_name`, `system_name`), so plugging a device in or out no longer switches the recording to another microphone. A chosen device missing from the list read at start shows as "(not connected)"; recording and dictation use the Windows default until it is plugged in. Dictation now also follows a microphone plugged in, or a default changed in Windows, after Ucho started.
- When the dictation model is missing, the Dictation screen no longer checks the model folder and logs the same warning many times a second: it looks every 5 seconds and logs once.
- `Ucho-Windows.zip` holds `Ucho\app\` instead of `Ucho\`: extracted to `C:\Users\<you>` it lands in `C:\Users\<you>\Ucho\app`, the path the README uses everywhere. `CHANGELOG.md` and the uninstaller are included.
- Installing inside a OneDrive folder now stops with a clear warning and asks before continuing (default: stop). `-Force` or a non-interactive run continues with a warning.
- The README suggests `claude mcp add -s user` (every project, not just the current folder) and has JSON and TOML snippets for Cursor, Claude Desktop and Codex. The speed claim is now 1 h in 4 to 7 min on Intel Arc (15x with a forced language, 8.9x with automatic language detection, `docs/benchmarks.md`).
- Version 0.2.0 in `ucho.config.VERSION`; the MCP server reports the same version instead of keeping its own copy.
- Models can be downloaded partially (`config.DOWNLOAD_PATTERNS`, used by `transcribe.model_path` both for the download and the offline check).

- `dictate.pyw` and the *Ucho Dictate* shortcut start Ucho with dictation open (or open it in the running Ucho). The installer creates *Ucho* and *Ucho Dictate* shortcuts on the Desktop and in the Start menu, both with the Ucho AppUserModelID.
- Dictation settings live in `settings.json` (`dictation_language`, `dictation_enter`, `dictation_mode`, `dictation_sounds`, `dictation_max_s`, `dictation_dictionary`, `dictation_preload`, `dictation_hotkey`); dictation logs to `ucho.log`. New keys `theme`, `layout`, `start_with_windows`, `setup_complete`.
- The record hotkey uses `RegisterHotKey` instead of a pynput keyboard listener: other programs no longer also receive Ctrl+Alt+R, and a combination taken by another program is shown in the window. `pynput` is no longer a dependency.
- New app icon drawn from the ear mark of the design system.
- PortAudio is initialized and closed under one lock (two threads doing it at once crashed the process in the merged app).

- The installer runs `python -m ucho.hardware --save` after installing the packages and downloads the recommended model instead of always large-v3 INT8. Re-running it keeps model and device choices made by hand (`--keep-choice`).
- **All code is in English** (workstream W0). English is the UI source language; the Polish translation moved to `ucho/locale/pl.json` (`en.json` is gone). Renamed:
  - scripts: `instaluj.ps1` → `install.ps1` (switches `-SkipModel`, `-WithSummary`, `-ReinstallPackages`), `uruchom.pyw` → `ucho.pyw`, `dyktuj.pyw` → `dictate.pyw`, `mcp_serwer.py` → `mcp_server.py`, `Ucho (diagnostyka).cmd` → `Ucho (diagnostics).cmd`;

  - settings keys: `katalog_nagran` → `recordings_dir`, `jezyk` → `language`, `jezyk_interfejsu` → `ui_language`, `sciezki` (`obie/mikrofon/system`) → `tracks` (`both/microphone/system`), `mikrofon_index` → `microphone_index`, `transkrybuj_po_stopie` → `transcribe_after_stop`, `podsumowanie` → `summary_enabled`, `model_llm` → `summary_model`, `zmiana_nazwy` → `rename_folder`; Dictate: `jezyk` → `language`, `tryb` (`wklej/pisz`) → `mode` (`paste/type`), `dzwieki` → `sounds`, `maks_nagranie_s` → `max_recording_s`, `slownik` → `dictionary`;

### Compatibility

- On first start `ustawienia.json` and `dyktuj.json` are migrated to `settings.json` and `dictate.json` (the old files are kept; a stored recordings folder is kept as it is), and `modele\` is renamed to `models\`.
- The app (recordings list, re-transcribe, re-summarize) and the MCP server read v0.1 and Nagrywacz archives with Polish file names and `meta.json` keys. A re-transcribed or re-summarized old session is saved in the new format.
- The MCP server still accepts the old Polish argument names, `--katalog` and `UCHO_NAGRANIA`.
- A microphone or system-audio device chosen by index (`microphone_index`, `system_index`, also `mikrofon_index` from v0.1) is turned into its name once the device list is read. An index that pointed at the MME "Sound Mapper" or the DirectSound "Primary Sound Capture Driver" becomes the default.
- The installer removes the v0.1 `Ucho Dyktuj.lnk` shortcuts and `Ucho (diagnostyka).cmd`.
- `dictate.json` (or v0.1 `dyktuj.json`) is imported into `settings.json` once and kept; a dictation model set by hand there is kept, the old default is not (the hardware recommendation wins). `dictate.example.json` is gone. Quit an older *Ucho Dyktuj* before starting v0.2: it holds Ctrl+Shift+Space.
- The last dictated text is read from `ucho.log`, else from the old `dictate.log`.
